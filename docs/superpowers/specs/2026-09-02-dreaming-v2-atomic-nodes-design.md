# Dreaming v2 설계안 — 노드 하나, 쓰기 둘, 읽기 둘, 그리고 120턴 시나리오

작성일 2026-09-02, 3판. 상태: **검토용 초안** (승인 전 구현 착수 금지).
HTML 아티팩트(그림·시나리오 포함): https://claude.ai/code/artifact/054854ca-b0f4-4844-bc52-3ae45c1e20ba

## 도입

- **무엇에 대한 문서인가**: Dreaming — RisuAI(AI 캐릭터 롤플레잉 채팅 프로그램) 앞에 놓이는 리버스 프록시로, 긴 대화를 압축하고 장기기억을 주입하되 LLM 프롬프트 캐시를 깨지 않는 것을 목표로 하는 메모리 엔진 — 의 메모리 설계 최종 후보입니다.
- **왜 썼나**: 사용자가 "간단하지만 강력해야 한다, 재압축이 있어도 된다, 메모리 설계만 이야기하자"고 요구했고, 설계를 실제로 굴려 보는 자세한 시나리오를 요청했습니다.
- **이번에 한 일**: 2판의 큐레이션 페이지·구역별 문턱·시간 점수식을 전부 걷어내고 저장 단위 하나·쓰기 둘·읽기 둘·상태 하나로 줄였습니다. 그 설계를 실제 100턴 벤치 대화의 사실(겨울 산 고택의 수호자 소연과 방문객 렌)을 재료로 t=0부터 t=200까지 턴별로 굴려, 각 시점에 프롬프트가 어떻게 생겼고 캐시가 언제 깨지고 기억이 어떻게 돌아오는지 적었습니다.
- **읽고 나서**: 독자는 이 설계가 어떤 순간에 무엇을 하는지 시나리오로 따라갈 수 있고, 아직 정할 값 다섯 개(N, 구역 폭, 통합 묶음, 소환 예산, 소환 키 유무)를 알게 됩니다.

### 지난 이야기

1판은 v1 골격에 HypaPlus식 노드와 예산 레인을 얹었고, 2판은 사람 기억처럼 거리에 따라 프리픽스가 흐려지는 구역(A/B/C)을 도입했습니다. 검토에서 사용자가 "큐레이션 페이지·구역별 문턱까지 가면 너무 복잡하다, 메모리 설계만 간단하고 강력하게"라고 했습니다. 3판은 그 요구대로 줄인 설계와, 그 설계를 검증하기 위한 상세 시나리오입니다.

### 용어

| 용어 | 뜻 |
|---|---|
| 프리픽스 | 요청에서 프롬프트 캐시 대상이 되는 앞부분. 1바이트라도 바뀌면 그 뒤 캐시가 전부 무효가 됩니다. |
| 노드 | N턴 배치에서 LLM이 한 번에 뽑아낸 기억 한 개. 사건(event)과 사실(fact) 두 종류. |
| 배치 | N턴(설정값, 기본 10)을 묶은 단위. 배치가 닫히면 유휴 시간에 Dreamer가 그것을 읽습니다. |
| 구역 | 현재 턴에서 얼마나 떨어져 있느냐로 나눈 프리픽스의 해상도 등급. 원문 꼬리 → A → B → C 순으로 흐려집니다. |
| 소환 | 프리픽스에 보이지 않는 노드를 마지막 두 메시지의 단어·키로 찾아 마지막 사용자 메시지 앞에 넣는 일. 캐시 밖. |
| 슬롯 | 소지금·위치·시각처럼 값이 바뀌는 상태 항목. 코드가 커밋 기록을 리플레이해 현재값을 냅니다. |

## 1. 설계 전부

### 저장 단위 하나

```
노드 = { id, batch, turn, kind: "event" | "fact",
         text,                            // event: 장면 1~3문장 / fact: 문장 1개
         dialogues: [{speaker, text}],    // event만, 원문 그대로
         characters: [str],
         keys: [str] }                    // Dreamer가 붙인 소환어 몇 개 (로어북 키와 같은 것)
```

이것뿐입니다. 버전 체인·근거 포인터·POV 필드는 없습니다. 노드는 한 번 쓰면 바뀌지 않습니다.

### 쓰기 둘 — 둘 다 유휴 시간, LLM 1콜씩

1. **추출.** N턴 배치가 닫히면 Dreamer가 그 배치 원문(+ 직전 배치 사건 노드 + 기존 사실 최대 50개 + 인물 목록)을 읽고 노드들과 슬롯 커밋을 냅니다. 출력은 턴별 사실 열거를 먼저, 사건을 나중에 쓰게 강제합니다.
2. **통합.** 배치 M개(기본 4)가 80턴 밖으로 나가면 Dreamer가 그 사건 노드들을 **챕터 노드 1개**로 다시 씁니다(재압축). 같은 구간의 사실 노드는 중복을 병합합니다. 원래 노드는 저장소에 남습니다.

### 읽기 둘

1. **프리픽스** (캐시 안, 결정론 렌더, LLM 0콜). 거리에 따라 같은 노드를 다르게 보여줍니다.

| 구역 | 거리 | 보이는 것 | 배치당 토큰 |
|---|---|---|---|
| 꼬리 | 0~15턴 | 원문 그대로 | ~12,000 |
| A | 15~40턴 | 사건 문장 + 대사 전부 + 사실 전부 | ~3,500 |
| B | 40~80턴 | 사건 문장만 | ~1,000 |
| C | 80턴~ | 챕터 노드 (배치 4개 → 1개) | ~300 / 4배치 |

강등은 배치가 닫히는 순간에 함께 일어납니다. 프리픽스 변경은 N턴에 1회입니다.

2. **소환** (캐시 밖, 마지막 user 앞). 후보는 **프리픽스에 안 보이는 노드** — B 구역의 사실·대사, C 구역의 사실·대사·사건 문장. 마지막 두 메시지에 노드의 `keys` 또는 단어가 걸리면 후보가 되고, 걸린 개수순 → 동률이면 최근순으로 예산 3,000자까지 넣습니다. 거리별 문턱·시간 점수식·임베딩은 없습니다.

### 상태 하나 — 캐시 밖, 항상

Dreamer가 낸 슬롯 커밋(`{slot, op: set|add, value, turn}`)을 코드가 리플레이해 현재값을 만들고 매 턴 마지막 user 앞에 넣습니다. 인물 목록은 최근 A 구역 노드의 `characters`를 코드가 집계합니다. LLM이 쓰는 페이지는 없습니다.

**HypaPlus와의 차이는 셋뿐입니다.** 거리별 렌더(캐시 안에 오래된 이야기를 흐려서 둠), 통합(재압축), 슬롯(상태는 검색하지 않음). 뺀 것은 시간 점수식과 임베딩입니다.

## 2. 프롬프트 모양 — t=100 시점

```
┌ system (카드 + 프리셋 + 상수 로어)                     ← BP1
│ [줄거리]  챕터 노드 (배치 1~4 → 1개)                     C
│ [지난 이야기 · 배치 5] 사건 문장들                        B
│ [지난 이야기 · 배치 6] 사건 문장들                        B
│ [지난 이야기 · 배치 7] 사건 문장 + 대사 + [사실]           A   ← BP2 (첫 청크)
│ [지난 이야기 · 배치 8] 사건 문장 + 대사 + [사실]           A
│ 원문 t=86 … t=100 (user/assistant 그대로)                꼬리 ← BP3
├─────────────────────────────────── 여기까지 캐시 ───────
│ [현재 상태] 소지금 450 · 위치 골짜기 · 시각 겨울 밤 · 동행 소연
│ [기억] 소환된 노드 0~K개 (이번 턴 단서에 걸린 것)
│ keyed 로어북 델타 (기존 lore_shift)
└ 마지막 user 메시지
```

## 3. 시나리오 — 겨울 산 고택, t=0부터 t=200까지

재료는 순정 건초더미 100턴(방문객 렌이 겨울 산의 고택에서 수호자 소연을 만나는 이야기)의 실제 사실들입니다. 턴 배치는 시나리오용 예시이며, 프롬프트 안의 문장은 설계가 만들 렌더의 모양을 보이기 위한 것입니다.

### t=0 설정
- N=10, 꼬리 15턴, A 끝 40턴, B 끝 80턴, 통합 묶음 M=4, 소환 예산 3,000자, 상한 64K.
- 카드 소연 + 뮈토스 6.2 프리셋 → system 11,800토큰. 출력 예약 6,000. 저장소 비어 있음.

### t=1 … 9 — 아무 일도 안 한다 (캐시: 매턴 append 히트)
프리픽스 = system + 원문 9턴. 프록시는 pair 원장에 해시만 적고 통과시킵니다. 마지막 user 앞에는 아직 넣을 것이 없습니다. t=3에서 렌이 "은자 500냥을 챙겨 왔다"고 말하지만 아직 아무도 읽지 않았습니다.

### t=10 — 배치 1 닫힘 → 유휴 5분 뒤 Dreamer 추출 (캐시: 프리픽스 변화 없음)
Dreamer가 원문 10턴을 읽고 냅니다(출력 일부 모양):

```json
{
  "per_turn": [
    {"turn": 1, "facts": ["렌은 원래 산 아래 마을로 향하던 중이었다.", "안개가 길을 속여 렌을 산 위로 이끌었다."]},
    {"turn": 3, "facts": ["렌은 은자 500냥을 지니고 있다."]},
    {"turn": 5, "facts": ["소연은 위지 가문 고택의 수호자다.", "소연의 양어머니 위지례는 전임 수호자였다."]},
    {"turn": 8, "facts": ["소연은 몸을 덥히는 데 좋다며 생강과 꿀을 섞어 말린 것을 내주었다.",
                          "생강과 꿀이 담긴 용기는 자색 유리병이다."]}
  ],
  "events": [
    {"start_turn": 1, "end_turn": 4, "location": "고택 앞마당", "characters": ["렌","소연"],
     "content": "안개에 길을 잃은 렌이 겨울 산 고택에 닿아 소연과 처음 마주친다. 소연은 경계하며 용건을 묻는다.",
     "dialogues": [{"speaker":"소연","text":"이 산에 무슨 볼일이지."}, {"speaker":"렌","text":"길을 잃었습니다. 하룻밤만 청합니다."}],
     "open_threads": ["렌이 산 아래 마을로 가려던 진짜 목적"]},
    {"start_turn": 5, "end_turn": 10, "location": "고택 안채", "characters": ["렌","소연"],
     "content": "소연이 렌에게 저녁을 차려 주고, 자색 유리병에서 생강과 꿀을 섞어 말린 약재를 꺼내 준다. 위지례가 살아있을 때 이후 처음으로 누군가와 마주 앉아 식사했다.",
     "dialogues": [{"speaker":"소연","text":"상 좀 차려주게. 건넌방 문 앞에 밥상이 있을 거야."}, {"speaker":"소연","text":"몸 덥히는 데 좋아. 생강과 꿀을 섞어 말린 것이다."}]}
  ],
  "commits": [{"slot":"소지금","op":"set","value":500,"turn":3}, {"slot":"위치","op":"set","value":"고택 안채","turn":5}],
  "actors": [{"names":["소연","위지소연","수호자"],"tier":"main"}, {"names":["위지례"],"tier":"support"}]
}
```

코드가 대사 4줄이 원문의 부분문자열인지, 숫자 500이 원문에 있는지 확인하고, 사실 7개에 `turn`과 `keys`를 붙여 저장합니다. keys는 같은 콜에서 Dreamer가 붙입니다 — 예: 생강·꿀 사실에 `["약", "생강", "꿀", "유리병", "몸 덥히다", "따뜻"]`. **프리픽스는 그대로입니다.** 배치 1은 아직 꼬리 안이라 원문으로 보입니다. 추출은 캐시를 건드리지 않습니다.

### t=25 — 배치 1이 꼬리 밖으로 → A 렌더 등장 (캐시: 프리픽스 변경 1회)
배치 1의 거리가 15를 넘습니다. 프리픽스에 처음으로 렌더된 청크가 들어갑니다:

```
[지난 이야기 · 배치 1 (t=1~10)]
(고택 앞마당 · 렌, 소연) 안개에 길을 잃은 렌이 겨울 산 고택에 닿아 소연과 처음 마주친다. 소연은 경계하며 용건을 묻는다.
  소연: "이 산에 무슨 볼일이지."
  렌: "길을 잃었습니다. 하룻밤만 청합니다."
  남은 실마리: 렌이 산 아래 마을로 가려던 진짜 목적
(고택 안채 · 렌, 소연) 소연이 렌에게 저녁을 차려 주고, 자색 유리병에서 생강과 꿀을 섞어 말린 약재를 꺼내 준다. …
  소연: "상 좀 차려주게. 건넌방 문 앞에 밥상이 있을 거야."
  소연: "몸 덥히는 데 좋아. 생강과 꿀을 섞어 말린 것이다."
[사실]
- 렌은 원래 산 아래 마을로 향하던 중이었다.
- 안개가 길을 속여 렌을 산 위로 이끌었다.
- 렌은 은자 500냥을 지니고 있다.
- 소연은 위지 가문 고택의 수호자다.
- 소연의 양어머니 위지례는 전임 수호자였다.
- 소연은 몸을 덥히는 데 좋다며 생강과 꿀을 섞어 말린 것을 내주었다.
- 생강과 꿀이 담긴 용기는 자색 유리병이다.
```

이 청크가 BP2 자리입니다. 이후 t=35, 45, 55, … 마다 배치 하나가 A로 들어오고, 그 순간에만 프리픽스가 바뀝니다. 마지막 user 앞에는 이제 `[현재 상태] 소지금 500 · 위치 고택 안채`가 매턴 붙습니다.

### t=42 — 렌이 약방에서 은자 50냥을 쓴다 (캐시: 히트)
t=50에 배치 5가 닫혀 Dreamer가 `{"slot":"소지금","op":"add","value":-50,"turn":42}`를 내면 코드가 리플레이해 `소지금 450`이 됩니다. 그 뒤 매 턴 `[현재 상태] 소지금 450 · 위치 마을 약방`이 항상 있습니다. 모델이 "돈이 얼마 남았지"를 알기 위해 아무것도 검색할 필요가 없습니다. 같은 배치에서 사실 노드 "약방 아랫목에 놓인 감초 뭉치가 오래되었으니 새 것은 내년 봄에 구해야 한다"(keys `["감초","약방","아랫목","약재","내년 봄"]`)도 나옵니다.

### t=50 — 배치 5 닫힘 → 배치 1이 A에서 B로 (캐시: 프리픽스 변경 1회, 동시에)
배치 3이 꼬리 밖으로 나와 A로 들어오고, 배치 1의 거리가 40을 넘어 B로 내려갑니다:

```
[지난 이야기 · 배치 1 (t=1~10)]
(고택 앞마당 · 렌, 소연) 안개에 길을 잃은 렌이 겨울 산 고택에 닿아 소연과 처음 마주친다. 소연은 경계하며 용건을 묻는다.
(고택 안채 · 렌, 소연) 소연이 렌에게 저녁을 차려 주고, 자색 유리병에서 생강과 꿀을 섞어 말린 약재를 꺼내 준다. …
```

대사 4줄과 사실 7개가 프리픽스에서 사라졌습니다(3,500 → 1,000토큰). 사라진 것들은 저장소에 그대로 있고, 이 순간부터 **소환 후보**가 됩니다. 두 변경이 한 요청에 몰렸으므로 캐시 파괴는 1회입니다.

### t=55 — "그때 주신 것 덕분에 따뜻해졌는데, 뭘 넣으셨나요" — B 구역에서 소환 (캐시: 히트)
마지막 두 메시지의 단어: 바람, 차다, 목, 따끔, 그때, 건네다, 따뜻, 넣다.

| 후보 노드 | 걸린 것 | 결과 |
|---|---|---|

v1 실측에서 같은 질문에 모델이 "생강과 약초"라고 답해 꿀을 빠뜨렸습니다. 그때는 요약문 한 줄만 있었습니다. 이번엔 원문 대사가 같이 갑니다. 자색 유리병 사실은 이번 단서에 안 걸려 안 갔습니다 — 묻지 않은 것은 안 줍니다.

### t=60 — 사용자가 t=60 응답을 리롤한다 (캐시: 히트)
배치 6(t=51~60)은 t=60 응답이 확정돼야 닫힙니다. pair 원장이 `reroll`을 판정하고 배치 6의 pair 목록에서 옛 해시를 새 것으로 바꿉니다. 배치가 아직 안 닫혔으므로 Dreamer는 옛 텍스트를 본 적이 없습니다. 이미 추출된 배치를 건드리는 편집(`diverged`)이면 그 배치를 `stale`로 표시하고 다음 유휴에 통째로 다시 추출합니다. 노드 단위 부분 무효화는 하지 않습니다.

### t=70 — 배치 7 추출이 실패한다 (캐시: 히트)
300초 타임아웃. 배치 원장에 `status: failed, fail_reason: "timeout"`. 채팅은 영향 없음. t=85에 배치 7이 꼬리 밖으로 나갈 차례가 오면 노드가 없으므로 **원문 그대로 프리픽스에 남깁니다**(꼬리가 10턴 길어질 뿐). 다음 유휴에 재시도해 성공하면 배치 닫힘 시점에 맞춰 A 렌더로 교체합니다 — 파괴 횟수를 늘리지 않습니다.

### t=90 — 배치 9 닫힘 → 배치 1이 80턴 밖으로 → 통합(재압축) (캐시: 프리픽스 변경 1회, 동시에)
Dreamer가 두 번째 종류의 콜을 합니다: 배치 1~4의 사건 노드 8~12개를 읽고 챕터 노드 1개를 씁니다.

```json
{"kind": "chapter", "batches": [1,2,3,4], "turns": [1,40],
 "text": "안개에 길을 잃은 렌이 겨울 산 고택에서 수호자 소연을 만난다. 소연은 경계하면서도 저녁과 약재를 내주고 하룻밤 머물기를 권한다. 렌은 사흘 뒤 도성에서 구한 설록차를 들고 재방문하고, 소연은 처음으로 미소를 보인다. 렌이 '준'이라는 아이의 행방을 묻자 소연은 모른다고 답한다. 무덤터 곁을 지나던 렌이 잿빛 개를 본다.",

```

같은 콜에서 배치 1~4의 사실 노드 중복을 병합합니다. 원래 노드는 지우지 않습니다. 프리픽스에서 B 청크 4개(약 4,000토큰)가 챕터 1개(약 300토큰)로 바뀝니다. Anthropic이면 유휴 5분에 캐시가 이미 만료돼 이 재압축은 공짜이고, DeepSeek처럼 유휴와 무관한 캐시면 N턴 1회 파괴에 포함됩니다 — 어느 쪽이든 추가 파괴는 없습니다.

### t=95 — "그때 무덤터 곁에서 저를 보셨다면 제가 들고 있던 자색 물건도 보셨을까요" — C 구역에서 소환 (캐시: 히트)
87턴 전 일입니다. 프리픽스에는 챕터 한 줄에 "무덤터"와 "잿빛 개"만 남아 있습니다. 단어: 무덤터, 곁, 보다, 들다, 비바람, 품속, 자색, 빛깔, 물건.

|---|---|---|
| 사실 (t=8) "생강과 꿀이 담긴 용기는 자색 유리병이다." | 단어 `자색` — 1개 | 소환 |

v1 실측에서 이 질문은 지식 블록에 "자색 유리병"이 있었는데도 실패했습니다 — 답한 것이 소연이 아니라 수색대장이었습니다. 이 설계도 그것까지는 못 고칩니다. 설계가 책임지는 것은 "필요한 문장이 마지막 user 앞에 있었는가"까지이고, 그것을 니들 오라클로 잽니다.

## 4. 열린 값 5개

1. **N** — 10 vs 15. 15면 캐시 파괴 6회, 배치당 Dreamer 입력 18K.
2. **구역 폭** — A 끝 40 / B 끝 80. A를 25로 줄이면 프리픽스 6K 가벼워지고 소환 의존이 커집니다.
3. **통합 묶음 M** — 4 (40턴 → 챕터 1개). 8이면 챕터가 더 거칠어지고 콜은 절반.
4. **소환 예산** — 3,000자. 시나리오에서 한 턴에 3개(600토큰)면 충분했습니다. 1,500자로 줄여도 될 수 있습니다.
5. **소환 키** — Dreamer가 붙이는 `keys`를 둘지, 순수 단어 겹침만 쓸지. t=55 예에서 "따뜻"은 key로만 걸렸습니다(원문은 "덥히는"). 키가 없으면 대사 한 줄만 소환됐을 것입니다.
