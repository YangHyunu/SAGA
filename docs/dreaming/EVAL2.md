# 평가 방법론 v2 — 딥리서치 종합 (2026-08-06)

ev1(30턴/프로브 6/단일 실행)은 하네스 배관 검증용으로 강등. 아래는 학술 벤치
5종 + 아카라이브 실측(The Seed 원문 확보) + 로컬 논문 조사 통합 결과로 재설계한
정식 프로토콜이다.

## 1. 리서치 근거 요약

### The Seed 디렉터 방식 (아카 원문 확보 — 177672953, 177850233)

- **80턴 3단계**: 지식 주입 12턴 → 장문 문맥 압박 28턴 → 평가 40턴.
- **평가 40턴 내부**: 직접 회상 24턴(이름/날짜/장소/가격/암호/상태변화 ~23항목)
  → 거짓 전제 저항 8턴(틀린 정보 섞어 질문 → 정정/"근거 없음" 요구) → 단기기억
  4턴(물건 위치 이동 등 최근 변화 추적) → 종합 일관성 4턴(복합+거짓 전제 혼합).
- **55점 = 55개 pass/fail 체크 합** (가중치 표 아님).
- **거리 기반 프로브 정의**: "충분히 멀어진 사실만 자연스러운 이야기 질문으로
  재질문. evict된 사실은 실제 가시 창 밖으로 나간 뒤에만 출제. 거리 bucket이
  아니라 실제 token distance + outside-visible-window 플래그를 함께 본다."
  → **우리 트림 밖 프로브 사상과 동일. 이 부분은 ev1이 이미 옳았다.**
- 하드 게이트: 정량 정확도 95%+, 문맥 90%+, 사실 안전성 95%+(unsupported 5%↓),
  RULER형 7종 80%+, probe trace 100% — "평균이 좋아도 증거 빠지면 실패".
- DIRECTOR(Gemini Flash) 7단계 폐쇄 루프: 입력 생성 → 안전 검사 → 교정/재시도
  → 실행 → 동적 사실 추출 → 거리 기반 probe → 이중 채점+원장 기록.
- 10막·80비트·고정 anchor 29개 동일 스토리를 150K/350K/550K 3규모에 재사용.

### 학술 벤치 (LongMemEval·LOCOMO·MemoryAgentBench·EMem·Forgetting Curve)

- 프로브 5대 카테고리: 정보추출 / multi-hop / 시간추론 / **지식갱신** /
  **abstention**(거짓 전제 — LOCOMO는 전체 문항의 24.9%).
- 간섭 설계: distractor 속에 evidence를 파묻는 haystack 구조가 표준.
- 채점: 문자열 매칭 단독은 거짓음성 위험 — LongMemEval judge는 사람과 97% 일치.
  LOCOMO는 "정답을 원문 그대로 발췌 가능하게" 문항을 설계해서 문자열 매칭 성립.
- 통계: EMem이 유일하게 3회 반복 mean±std 명시. 프로브 6개 단일 실행은 1문항
  뒤집힘 = 16.7%p 요동이라 비교 무의미.
- 규모: 공인 최소축 LOCOMO ~300턴/35세션. 30턴은 최소 공인 벤치의 1/10.
- **스펙 §9 인용 교정**: 2511.17208은 EMem(EDU 표현법) 논문. turn-retrieval
  베이스라인의 정확한 출처는 **2604.11628 "Back to Basics: Let Conversational
  Agents Remember with Just Retrieval and Generation"** (TIR은 논문 내 기법명).
- 주의: The Seed 글 제목의 "Letta"는 실제 Letta(MemGPT)사와 무관한 코히바블랙
  본인의 프로젝트 코드명 (© CohibaBlack) — 인용 시 혼동 방지.

### 커뮤니티 신뢰 포맷 (아카)

- 최상위 신뢰 = 상단 정량 요약 블록(턴수·완주율·점수·비용·응답시간) + 접이식
  턴별 원문(감사용) + 오답 사유 before/after 표기. 표/원문 없는 주장 = 감상평
  취급. 우리 report.py 포맷과 이미 수렴 — 오답 사유 표기만 추가하면 됨.
- 유저 체감: "20만(KB 환산 ~200KB) 넘어가면 슬슬 고장", 요약 로어북 1~2K 토큰
  유지, 상시활성 총 1만 토큰 이하 권장이 경험칙.

## 2. v2 프로토콜

### 대본: 80턴 3단계 (The Seed 구조 이식)

| 구간 | 턴 | 내용 |
|---|---|---|
| 주입 | 1~14 | 지뢰 ~20개: 정확값(이름/나이/가격/개수/시각/암호), 관계, 상태. **지뢰·프로브 턴은 고정 대사**(시뮬레이터 0관여), 필러만 시뮬레이터 |
| 압박 | 15~40 | distractor 삽입 — 유사 숫자·이름·제3자 소문(간섭 설계). 이 구간에서 **지식 갱신 이벤트** 2~3개(소지금 변동, 약속 시각 변경) |
| 평가 | 41~80 | 5유형 프로브 ~40체크: 직접 회상 ~20 / 거짓 전제 8 / 지식 갱신 4 / multi-hop 4 / 단기(윈도우 안 대조) 4 |

- 모든 프로브에 **실제 token distance + outside-visible-window 플래그** 기록
  (The Seed 방식) → 거리별 회수율 곡선 산출.
- 단기 4문항은 대조 장치: 메모리 시스템이 최근 컨텍스트를 해치지 않는지.

### 채점: 이중 오라클

1. **결정론 오라클** (기존): 정확값 프로브 — 고정 대사가 "숫자를 말해줘" 형태로
   강제해 문자열 매칭이 성립하도록 문항 설계 (LOCOMO 방식).
2. **LLM judge** (신규): 거짓 전제("전제를 사실로 단정했는가 Y/N" 이진 프롬프트),
   패러프레이즈 회수, 종합 일관성. 이진 판정으로 좁힐수록 신뢰도↑.
3. 감사용 원문 + 오답 사유 before/after 병기 (커뮤니티 포맷).

### 지표 (변형별)

회수율(유형별 분해) / abstention 정확도(별도 축 — 헛기억 확신이 "모른다"보다
나쁨) / 거리별 곡선 / $ / 캐시율 / 턴 준비시간. 하드 게이트는 The Seed 기준
차용하되 1차엔 관측만.

### 실행 규모

- 카드: 대화형(소연) 주력 + REALM 보조(연출 헤비 카드 일반화 확인).
- 반복: **3회 mean±std** (필러 시뮬레이터 시드만 변동, 지뢰·프로브 고정).
- 대조군: dreaming / vanilla / trim / turn-retrieval (인용은 2604.11628로 교정).
- 비용 추정: 80턴×4변형 ≈ $11/회, 3반복 전체 ≈ **$30~35**. 절충: 4변형 1회
  + (dreaming vs retrieval) 2변형만 3반복 ≈ **$18~20**.
- 300턴+/멀티세션 스트레스는 v2.1로 이월 (record/replay 하네스 결합 후).

## 3. 측정 도구 3분할 (2차 리서치 반영 — 합성 vs 실측 격차 대응)

단일 도구로 모든 주장을 재는 것이 설계 오류. 주장별 도구 분리:

| 주장 | 도구 | 근거 |
|---|---|---|
| 캐시를 지킨다 ($·캐시율) | **실와이어 record/replay** (진짜 RisuAI 캡처 corpus + 턴 간격 재현 — TTL 5m 만료 포함) | 합성 드라이버는 턴 간격 ~5초라 TTL 만료가 없어 히트율 과대측정. ev1의 64.4%에 이 각주 필수 |
| 기억을 되살린다 (회수·abstention) | **합성 프로브 벤치** (v2) | 실유저 로그엔 정답 라벨이 없어 채점 불가 — 통제 실험이 유일한 방법. 공개 RP 벤치 전부(rp-benchmark, ping_pong_bench, RPBench-Auto, RP-Leaderboard, CharacterBox) 합성 방식 |
| 실제 앱에서 돌아간다 | **진짜 RisuAI 라이브 스모크** (소수 턴, 수동/브라우저) | RisuAI엔 SillyTavern STscript(/while /times /trigger)류 반복 매크로 층이 없어 앱 내 자동 벤치 불가 확인 — 스모크만 실앱 |

합성 벤치 충실도 완화책 (v2 대본에 반영): 토큰 기반 트림(8쌍 고정 대신 RisuAI maxContext 로직), 리롤 2회+수정 1회 삽입, max_tokens 1000, 프리셋 장착 변형 1종, TTL 걸치는 랜덤 대기.

### 지뢰 방식 전환: 명시 대사 → 동적 사실 추출

"숫자 300을 명시하라"식 강제 대사는 부자연 + The Seed도 안 씀. The Seed DIRECTOR
방식 채택: **롤플레이가 자연히 만든 사실(캐릭터가 부른 가격·인명·사건)을 디렉터
LLM이 턴마다 추출해 라벨로 기록**하고, 거리 조건 충족 후 그 사실을 자연스러운
질문으로 되묻는다. 사전 심기는 지식 갱신 이벤트 등 반드시 발생시켜야 할 패턴에만
최소 사용.

### LLM judge 설계 원칙 (커뮤니티+메타벤치 실증)

- judge는 피평가 모델보다 강한 모델 (자기선호편향 방지), temperature 0
- 이진 체크 다수 + 개방형 소수 혼합 (RP-Leaderboard: Yes/No 25 + 0-100 3)
- **judge 자체를 검증**: PersonaEval 경고 — 최고 judge도 역할 식별 69% vs 인간
  90.8%. rp-benchmark는 judge-실사용자 불일치(50.7% vs 38.7%)를 자인. §9의
  10~20% 수동 감사 표본으로 judge-사람 일치율을 먼저 재고, 95%+일 때만 신뢰.

## 4. 커뮤니티 5면 조사 반영 (2026-08-06, 소넷 5에이전트)

렌즈: 봇 제작자 QC / 프리셋 비교 / 도구 제작자 입증 / 일반 유저 치매 판정 / 타 커뮤 교차.

### 프로브 설계에 반영

1. **관계·정체성 연속성 축 신설** — "치매" 판정 빈도 1위는 사실 오류가 아니라
   "이 사람이 누군지, 무슨 사이인지"를 못 알아보는 순간. 사실 회상과 분리 채점.
2. **저장 실패 vs 활용 실패 분리 채점** — 커뮤가 이미 "치매"(정보 소실)와 "로어북
   씹힘"(있는데 참조 안 함)을 구분해 부름. 우리는 내부 저장소를 볼 수 있으므로
   프로브 미스마다 (a) 저장소에 없음 = Dreamer 추출 실패, (b) 저장소에 있는데
   응답에 안 나옴 = 주입/활용 실패로 원인 분해해 리포트. ev1의 miss 판독을
   자동화하는 것과 동일.
3. **계단식 토큰 임계 리포트** — 유저 체감이 "5만/10만/40만 토큰" 구간 언어로
   작동. 거리별 곡선을 토큰 구간 축으로도 표기.
4. **요약 유해 실증 (GeekNews 독립 실험)**: 합성요약 2.65 < 무메모리 3.30 <
   원본로그 4.55 < 하이브리드 4.95 — ev1의 "요약 명제 주입 무시" 관측과 동일
   패턴의 외부 재현. keyExcerpts(원문 발췌 병행 주입) 우선순위 근거 강화.

### 공개 포맷에 반영 (신뢰 관례)

- 동일 입력 고정 + temperature/시드 명시 (커뮤 최소 통제 관례)
- 무편집 전체 원문 공개 — 발췌·스샷보다 raw log가 신뢰 기준
- **파이프라인 단계별 시간 분해 표** (Agents! 유저 벤치 방식 — 이 채널에서
  유일하게 신뢰받은 정량 포맷): 단계별 소요시간·비중 + 기능 토글 A/B + 통제군 차감
- 다장르 시연 (한 카드가 아니라 장르 다른 카드 2종 이상)

### 메타 발견

아카 생태계에서 제작자 직접 정량 벤치는 The Seed 외 전무 — 도구 제작자 표준은
자기신고 수치 + 결과물 전시 + 커뮤 버그리포트 루프. **재현 가능한 벤치 자체가
차별화 포인트**이며, 공개 시 "자기신고가 아니라 재현 가능 벤치" 프레이밍을 걸 것.

## 5. ev1에서 유지되는 것

트림 밖 프로브 사상(=The Seed 거리 기반과 동일), 대본 동결, 대조군 4종, 결정론
오라클(정확값 한정), 비용·캐시 병기, 감사용 원문. 재설계되는 것은 규모(30→80턴),
프로브 수(6→~40), 유형(1→5), 채점(단일→이중), 반복(1→3회).
